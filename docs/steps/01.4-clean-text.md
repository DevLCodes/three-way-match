# Step 01.4: Clean the parsed text

**Goal:** remove Nemotron Parse's layout tags so the next step, LLM extraction, gets only the words and the table.

## Files

| File | What it is |
|---|---|
| [`src/three_way_match/clean.py`](../../src/three_way_match/clean.py) | `clean(content)` and an entry point that prints before and after |
| [`tests/test_clean.py`](../../tests/test_clean.py) | Box and class tags removed, tables and hyphenated classes handled, picture blocks dropped |

## Command

```bash
uv run python -m three_way_match.clean data/parsed/invoice_10250_p1.txt
```

## Output

Before: 783 characters, 30 tags (the full text is in [step 01.3](01.3-parse-page.md#output)).

After: 470 characters, 0 tags:

```
**INVOICE**

**Invoice Number:**10250

**Customer Name:**Hanari Carnes

**Salesperson:**Margaret Peacock

**Invoice Date:**2016-07-08

\begin{tabular}{cccc}
\thead{Product Name} & \thead{Unit Price} & \thead{Quantity} & \thead{Total Price}\\
Jack's New England Clam Chowder & \$7.70 & 10 & \$77.00\\
Manjimup Dried Apples & \$42.40 & 35 & \$1484.00\\
Louisiana Fiery Hot Pepper Sauce & \$16.80 & 15 & \$252.00\\
\mbox{} & \mbox{} & **Total:** & \$1813.00\\
\end{tabular}
```

Tests: `8 passed in 0.13s`.

## What happened

1. The text was split into blocks on blank lines (`\n\n`), the parser's block separator.
2. Any block tagged `<class_Picture>` was dropped. A logo or stamp has no text the matcher needs, and its tags would only add noise. This invoice has none, so all 6 blocks stayed.
3. One **regular expression** (a pattern for matching text) removed every tag: `<x_[\d.]+>|<y_[\d.]+>|<class_[\w-]+>`. Read it as: `<x_` followed by digits and dots, then `>`; or the same for `y`; or `<class_` followed by letters, digits, `_` or `-`, then `>`. The `-` matters for classes like `Page-header`.
4. 30 tags went (5 blocks × 4 box corners, 1 table × 4, plus 6 classes), and the text shrank by 40%, from 783 to 470 characters.

**What was kept, on purpose:** the `**bold**` labels and the LaTeX table. The labels tell the LLM which value is which ("Invoice Number:" → 10250), and the table keeps each product's price and quantity on the same row. Flattening the table to plain words would let values drift between rows.

**What was lost:** the bounding boxes. Fine for now; the design keeps provenance (where each value sits on the page) for the approval screen later, and the raw text with boxes stays in `data/parsed/`.

**Why it matters next:** fewer characters means fewer tokens sent to the LLM (cheaper and faster), and no tag can be mistaken for a value. Step 01.5 defines the exact shape the LLM's answer must have.
