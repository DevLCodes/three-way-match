# Step 01.5: Define the data models

**Goal:** fix the exact shape of an extracted document, so anything the LLM returns is checked before the matcher ever sees it.

## What happened

A **Pydantic model** is a Python class that describes data: each field has a type and rules. `Document.model_validate_json(text)` parses the JSON and checks every field in one go. It either returns a `Document` object, or raises `ValidationError` naming the field and the rule that failed.

The shape:

```
Document
  order_id   text, not empty
  doc_date   text or null
  party      text or null          (customer name)
  lines      list of LineItem      (required)
  total      exact decimal or null
LineItem
  product    text, not empty
  quantity   exact decimal, >= 0
  unit_price exact decimal >= 0, or null
```

Reading the 8 results:

1. **Valid invoice:** accepted. Money is a `Decimal`, Python's exact decimal type. `42.40` became `Decimal('42.4')`: the same value, written without the trailing zero. A `float` would store 42.4 as 42.39999…, and cents would drift when lines are added up.
2. **Null total:** accepted on purpose. If the document doesn't show a value, the LLM must say `null` rather than guess; the matcher then reports the missing total.
3. **`"$42.40"`:** rejected. The prompt in step 01.6 asks for plain numbers; this catches the LLM ignoring it.
4. **Negative quantity:** rejected by the `ge=0` rule (greater than or equal to 0).
5. **`"thirty-five"`:** rejected. Not a number.
6. **No `lines`:** rejected. Without lines there is nothing to match.
7. **Extra field `note`:** rejected because of `extra="forbid"`. This is a safety rule: a malicious PDF could try to smuggle instructions through an extra field, and the schema refuses anything it doesn't name.
8. **Not JSON:** rejected. LLMs sometimes chat ("Sure! Here is…") instead of answering in JSON.

`DocType` is an **enum**: a fixed set of three allowed names, so a typo like `"invioce"` can't create a fourth kind of document.

**Why it matters next:** step 01.6 asks the LLM for exactly this shape. When the reply fails validation, the error message above (field + reason) goes back to the LLM so it can fix its answer.
