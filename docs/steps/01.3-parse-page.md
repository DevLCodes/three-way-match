# Step 01.3: Parse one page with Nemotron Parse

**Goal:** send one page image to NVIDIA Nemotron 3.5 Parse and get back the text on the page, with its layout.

## Files

| File | What it is |
|---|---|
| [`src/three_way_match/parse.py`](../../src/three_way_match/parse.py) | `parse_page(image)`: one HTTP call per page, result cached in `data/parsed/` |
| [`tests/test_parse.py`](../../tests/test_parse.py) | Checks the request (URL, auth header, image bytes) and the cache, with a fake transport |

## Command

The API key lives in `~/.claude/.env`, outside the repo. `set -a` exports every variable the file defines.

```bash
set -a; . ~/.claude/.env; set +a
uv run python -m three_way_match.parse data/pages/invoice_10250_p1.png
```

Time: 2.3 s for the call. Tests: `5 passed in 0.17s`.

## What happened

1. `parse_page` sent one HTTP `POST` to `https://ai.api.nvidia.com/v1/retrieval/nvidia/nemotron-3.5-parse/parse` as a multipart form, the same format a browser uses to upload a file. It carried two parts: `document` (the PNG bytes) and `options` (`max_output_tokens` 4096, a cap on how much text the model may write).
2. The `Authorization: Bearer <key>` header proves the request is yours. The key is read from the environment, never written in code or output.
3. Nemotron Parse is a vision model: it looks at the pixels and writes out what it reads. The reply is JSON; the text is in its `content` field.
4. Each block of the page comes back as one paragraph:
   - `<x_0.3574><y_0.0359>` … `<x_0.4678><y_0.0547>` is the block's bounding box, as fractions of page width and height (top-left, then bottom-right). `INVOICE` sits 36–47% across and 4–5% down.
   - `<class_Title>`, `<class_Text>`, `<class_Table>` say what kind of block it is.
   - `**…**` marks bold text, in Markdown.
   - The line items come back as a LaTeX `tabular`: rows end in `\\\\`, cells are split by `&`, and `\$` is an escaped dollar sign.
5. The result was saved to `data/parsed/invoice_10250_p1.txt`, so this page is never sent again. That saves time and API quota.

Every value from the PDF is there: number, customer, date, three lines and the total.

**Why it matters next:** the tags are useful for knowing *where* a value is, but noise for extraction. Step 01.4 strips them and keeps the text and the table.
